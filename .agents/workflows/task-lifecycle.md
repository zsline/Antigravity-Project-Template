# Рабочий процесс: жизненный цикл задачи

## 1. Регистрация

Координатор:
1. Фиксирует потребность в `TASKS.md`.
2. Определяет ожидаемый результат.
3. Проверяет, не существует ли аналогичной задачи.
4. Создаёт отдельный файл задачи непосредственно в `tasks/` (кроме `tasks/templates/`) на основе `tasks/templates/TASK_TEMPLATE.md`. Подкаталоги по статусам не создаются.

Статус: `backlog`.

## 2. Уточнение

Координатор:
1. Изучает требования и связанные документы.
2. Уточняет неоднозначности.
3. Определяет границы изменений (для задач на разработку кода пути указываются строго внутри вложенной папки приложения `<project_name_lowercase>/`).
4. Формулирует критерии приёмки.
5. Выявляет зависимости и риски.

Если задача требует изменения утверждённых требований, необходимо согласование пользователя.

## 3. Подготовка

Перед началом выполнения:
- Все требования понятны.
- Критерии приёмки проверяемы.
- Зависимости выполнены или согласованы.
- Определена область изменений.
- Подготовлены необходимые инструкции и доступный контекст.

Статус: `ready`.

## 4. Назначение

Координатор:
1. Назначает одного ответственного исполнителя.
2. Определяет допустимые параллельные работы.
3. Проверяет, что нет конфликта по файлам и общим интерфейсам.
4. Передаёт исполнителю описание задачи и ссылки на документы.

Статус: `in-progress`.

## 5. Выполнение

Исполнитель:
1. Изучает код и документацию.
2. Реализует задачу в согласованных границах (исходный код размещается строго внутри вложенной папки приложения `<project_name_lowercase>/`; перенос кода в корень запрещён).
3. Добавляет или обновляет тесты.
4. Выполняет доступные проверки (команды сборщиков, пакетных менеджеров и тестов запускаются в рабочей директории вложенной папки приложения).
5. Обновляет документацию при необходимости.
6. Передаёт отчёт координатору.

Если обнаружены существенные препятствия, исполнитель сообщает о них координатору, а не принимает несогласованные решения.


## 6. Проверка

Координатор назначает ревьюера, если это оправдано масштабом и риском изменений.

Ревьюер:
- проверяет diff;
- сверяет результат с требованиями;
- оценивает качество и безопасность;
- проверяет результаты тестирования;
- выносит один из вердиктов: `APPROVED`, `CHANGES_REQUIRED`, `BLOCKED`;
- фиксирует замечания.

Статус задачи: `review`.

## 7. Исправления и реакция на ревью

В зависимости от вердикта ревьюера:
1. `APPROVED` — задача переходит к приёмке (может перейти в `done`, если выполнены все остальные критерии приёмки).
2. `CHANGES_REQUIRED` — задача возвращается в статус `in-progress`. Замечания ревьюера оформляются как конкретные исправления, исполнитель устраняет проблемы, после чего задача снова направляется на проверку (`review`).
3. `BLOCKED` — задача переводится в статус `blocked` (или остаётся в нём), если внешнее препятствие или недоступность зависимостей не позволяет продолжить проверку или приёмку.

## 8. Приёмка

Задача получает статус `done`, только если:
- получен вердикт ревьюера `APPROVED` (если ревью проводилось);
- все критерии приёмки выполнены;
- обязательные проверки пройдены;
- нет нерешённых блокирующих замечаний;
- документация актуальна;
- результат зафиксирован в отчёте.

## 9. Закрытие

Координатор:
- обновляет `TASKS.md`;
- обновляет `WORK_PLAN.md`, если изменился прогресс этапа;
- фиксирует необходимые решения в `DECISIONS.md`;
- отмечает оставшиеся проблемы и зависимости;
- определяет следующий доступный этап работы.

## 10. Правила статусов

### Статусы задачи:
- `backlog` — идея или запланированная задача.
- `ready` — требования уточнены, зависимости выполнены, задачу можно начинать.
- `in-progress` — идёт выполнение.
- `review` — реализация завершена, результат проверяется ревьюером.
- `blocked` — выполнение или приёмка невозможны из-за внешнего препятствия.
- `done` — критерии приёмки выполнены, проверки пройдены.

Статус `rejected` как отдельный статус задачи не используется: при необходимости доработок задача возвращается в статус `in-progress`.

### Вердикты ревьюера:
- `APPROVED` — критерии выполнены, замечаний нет (задача может перейти в `done`).
- `CHANGES_REQUIRED` — обнаружены замечания, требующие исправления (задача возвращается в `in-progress`).
- `BLOCKED` — проверку или приёмку невозможно продолжить из-за внешнего препятствия (задача переходит в `blocked`).

Каждый переход статуса должен отражать фактическое состояние задачи, а не желание ускорить отчётность.

Статус задачи отражается в её файле и синхронно обновляется в `TASKS.md`. Файлы задач остаются непосредственно в `tasks/` и не перемещаются по подкаталогам.
