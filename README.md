# Antigravity Project Template

## 1. Назначение

Универсальный шаблон для структурированной разработки программных проектов в Antigravity с использованием нескольких AI-агентов.

Шаблон помогает:

- организовывать документацию;
- разбивать работу на проверяемые задачи;
- распределять ответственность между агентами;
- контролировать качество;
- фиксировать архитектурные решения;
- передавать работу между агентами без потери контекста.

## 2. Быстрый старт и навигация

### 2.1. Создание нового проекта

- Порядок копирования шаблона и первичной настройки описан в [scripts/NEW_PROJECT.md](scripts/NEW_PROJECT.md).
- Не веди разработку непосредственно внутри исходного шаблона.

### 2.2. Исследование и подготовка (Discovery)

- Основной регламент подготовки проекта: [.agents/workflows/project-discovery.md](.agents/workflows/project-discovery.md).
- Стартовое задание для координатора: [docs/templates/PROJECT_START_PROMPT.md](docs/templates/PROJECT_START_PROMPT.md).
- Проектная документация создаётся на основе шаблонов в [docs/templates/](docs/templates/).
- Допуск к разработке осуществляется по чек-листу готовности [.agents/workflows/readiness-check.md](.agents/workflows/readiness-check.md).
- Дизайн-материалы хранятся в `design/`. Перед проектированием интерфейса агенты изучают доступные референсы и учитывают согласованные решения.

### 2.3. Жизненный цикл задач и разработка

- Подробные задания создаются непосредственно в каталоге [tasks/](tasks/) (кроме `tasks/templates/`) на основе [tasks/templates/TASK_TEMPLATE.md](tasks/templates/TASK_TEMPLATE.md).
- Реестр задач и текущие статусы ведутся в [TASKS.md](TASKS.md).
- Жизненный цикл каждой задачи регулируется регламентом [.agents/workflows/task-lifecycle.md](.agents/workflows/task-lifecycle.md).
- Параллельное выполнение координируется по регламенту [.agents/workflows/parallel-work.md](.agents/workflows/parallel-work.md).

## 3. Структура проекта

| Документ или каталог | Назначение |
|---|---|
| `AGENTS.md` | Общие правила для всех агентов |
| `.agents/rules/` | Специализированные правила ролей: координатор, разработчик, исследователь, ревьюер |
| `.agents/workflows/` | Повторяемые рабочие процессы: `project-discovery`, `task-lifecycle`, `parallel-work`, `readiness-check` |
| `PROJECT_CONFIG.md` | Текущая конфигурация проекта, статус и технологический стек |
| `profiles/` | Технологические профили: `laravel`, `wordpress`, `api`, `frontend` |
| `design/` | Дизайн-референсы, скриншоты, ссылки на сайты и макеты интерфейса |
| `docs/templates/` | Шаблоны спецификаций, требований, архитектуры и решений, включая `DECISION_TEMPLATE.md` |
| `docs/decisions/` | Подробные архитектурные решения (ADR) |
| `tasks/` | Файлы задач проекта. Хранятся непосредственно в каталоге; статус отражается в файле задачи и в `TASKS.md` |
| `tasks/templates/` | Шаблоны задач, включая `TASK_TEMPLATE.md` |
| `TASKS.md` | Сводный реестр задач |
| `WORK_PLAN.md` | Этапы реализации проекта |
| `QUALITY_CHECKLIST.md` | Чек-лист контроля качества |
| `DECISIONS.md` | Реестр принятых архитектурных решений |
| `CHANGELOG.md` | История изменений проекта |
| `scripts/` | Инструкции по созданию проекта из шаблона, включая `NEW_PROJECT.md` |

## 4. Правила параллельной работы

- Не назначай нескольким агентам одновременное изменение одних и тех же файлов без координации.
- Сначала согласовывай общие интерфейсы, схемы данных и контракты API.
- Фиксируй результаты исследований в документации.
- Передавай незавершённую работу через [docs/templates/AGENT_HANDOFF_TEMPLATE.md](docs/templates/AGENT_HANDOFF_TEMPLATE.md).
- Координатор отвечает за разрешение конфликтов и окончательную приёмку.

## 5. Важные ограничения

- Не считай сгенерированный код автоматически правильным.
- Не заявляй об успешных проверках, которые не запускались.
- Не допускай изменения архитектуры без согласования.
- Не храни секреты в репозитории.
- Не копируй в новый проект ненужные профили и документы.
- Поддерживай документацию в актуальном состоянии.

## 6. Критерий готовности проекта

Проект считается готовым к выпуску только после выполнения применимых критериев из `QUALITY_CHECKLIST.md`, проверки критических сценариев, устранения блокирующих проблем и подтверждения готовности координатором.
