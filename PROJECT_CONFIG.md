# Конфигурация проекта

## 1. Основная информация

- **Название проекта:** не задано
- **Папка приложения:** не задана (формируется в нижнем регистре: `<project_name_lowercase>/`)
- **Краткое описание:** не задано
- **Тип проекта:** не определён
- **Статус:** discovery
- **Ответственный за принятие решений:** пользователь

## 2. Технологический стек

Заполняется после согласования технических требований.

- **Языки программирования:** не определены
- **Основные фреймворки:** не определены
- **База данных:** не определена
- **Среда разработки:** не определена
- **Инфраструктура и развёртывание:** не определены
- **Внешние сервисы и API:** не определены

Не выбирай технологии только на основании значений по умолчанию. Сначала выясни требования и ограничения проекта.

## 3. Архитектурные ограничения

До согласования архитектуры действуют следующие правила:

- Соблюдать двухуровневую структуру: корень зарезервирован для управления и документации; исходный код, зависимости и конфигурации размещаются строго во вложенной папке приложения (`<project_name_lowercase>/`).
- Не создавать папку приложения и не инициализировать стек до завершения Discovery, прохождения Readiness Check и подтверждения пользователя.
- Единый Git-репозиторий размещается в корне проекта.
- Не добавлять зависимости без обоснования.
- Не менять утверждённую архитектуру без согласования.
- Не дублировать существующие компоненты.
- Не создавать параллельные реализации одной функции без необходимости.
- Документировать существенные технические решения.

## 4. Правила работы

- Общие правила для всех агентов находятся в `AGENTS.md`.
- Специализированные правила находятся в `.agents/rules/`.
- Рабочие процессы находятся в `.agents/workflows/`.
- Требования и архитектура фиксируются в документации проекта.
- Подробные задания хранятся в `tasks/`.
- Статусы и зависимости задач отражаются в `TASKS.md`.

## 5. Работа с неопределённостью

Если информация отсутствует:

1. Не выдавай предположение за утверждённый факт.
2. Укажи, какая информация отсутствует.
3. Оцени, блокирует ли это текущую задачу.
4. Если решение влияет на архитектуру, безопасность, стоимость или сроки, запроси согласование.
5. Зафиксируй принятое решение в соответствующей документации.
