# Общие правила проекта

## 1. Главные принципы
- Перед началом работы изучи документацию проекта.
- Соблюдай утверждённые требования и архитектуру.
- Не принимай существенные технические решения без согласования.
- Не расширяй поставленную задачу самостоятельно.
- Не дублируй существующую функциональность.
- Не изменяй код, не относящийся к текущей задаче, без необходимости.

## 2. Работа с документацией
- `PROJECT.md` — источник информации о целях проекта.
- `REQUIREMENTS.md` — источник функциональных требований.
- `ARCHITECTURE.md` — источник архитектурных решений.
- `DATABASE.md` — источник структуры данных.
- `WORK_PLAN.md` — источник последовательности этапов.
- `TASKS.md` — источник текущего состояния задач.
- `DECISIONS.md` — журнал согласованных решений.

Если документы противоречат друг другу:
1. Не выбирай решение самостоятельно.
2. Определи противоречие.
3. Сообщи координатору.
4. Дождись согласования.

## 3. Правила выполнения задач
- Выполняй только назначенную задачу.
- Перед работой проверь её зависимости и критерии приёмки.
- Изучи существующий код перед изменениями.
- Не начинай реализацию, если требования недостаточно определены.
- Разбивай слишком крупные задачи на небольшие подзадачи через координатора.
- Не отмечай задачу завершённой без проверки результата.

## 4. Работа нескольких агентов
- Каждая задача должна иметь одного ответственного исполнителя.
- Перед началом работы координатор определяет затрагиваемые файлы.
- Не редактируй файлы, назначенные другому исполнителю.
- Согласовывай изменения общих интерфейсов и контрактов до реализации.
- Не изменяй чужие незакоммиченные изменения.
- Перед объединением проверь совместимость изменений.
- При конфликте остановись и сообщи координатору.

## 5. Качество кода
- Следуй соглашениям и стилю существующего проекта.
- Избегай дублирования кода.
- Не добавляй зависимости без обоснования.
- Не удаляй существующую функциональность без согласования.
- Не храни секреты и пароли в исходном коде.
- Не отключай проверки безопасности ради прохождения тестов.

## 6. Тестирование
- Выполняй проверки, предусмотренные задачей.
- Не утверждай, что тесты пройдены, если они не запускались.
- Если тесты невозможно выполнить, укажи причину.
- При обнаружении ошибок исправляй их в пределах задачи.
- Не скрывай известные проблемы.

## 7. Документирование
- Обновляй документацию, если изменились требования, архитектура, API или поведение системы.
- Записывай согласованные архитектурные решения в `DECISIONS.md`.
- Не переписывай документы без необходимости.
- Не дублируй одну информацию в нескольких местах без причины.

## 8. Git
- Перед изменениями проверь состояние рабочего дерева.
- Не перезаписывай и не удаляй чужие изменения.
- Не выполняй принудительный сброс, очистку или переписывание истории без разрешения.
- Не создавай коммиты и не отправляй изменения в удалённый репозиторий без соответствующего разрешения.

## 9. Отчёт о выполнении
После выполнения задачи сообщи:
1. Что сделано.
2. Какие файлы изменены.
3. Какие проверки выполнены и каков результат.
4. Какие проблемы остались.
5. Соответствует ли результат критериям приёмки.

## 10. Приоритет
Безопасность данных и сохранность изменений важнее скорости выполнения.

Если задачу невозможно выполнить без нарушения этих правил, остановись и сообщи координатору.


## 11. Работа с дизайн-материалами

Перед проектированием или изменением пользовательского интерфейса проверяй каталог `design/` и изучай доступные референсы, макеты и описания.

- Учитывай материалы из `design/` при подготовке требований, архитектуры интерфейса и задач на разработку.
- Не считай визуальные предположения утверждёнными требованиями.
- Если референсы противоречат друг другу или утверждённой документации, сообщи координатору и дождись разрешения противоречия.
- До основной реализации согласуй с пользователем концепцию интерфейса и ключевые решения, если они ещё не утверждены.
- Если дизайн уже согласован, следуй утверждённым решениям и не запрашивай повторное согласование без существенной причины.
- Если референсы недоступны или их содержимое не удалось изучить, сообщи об этом и не утверждай, что анализ выполнен.
- Не изменяй и не удаляй предоставленные пользователем материалы без необходимости и разрешения.
