# Профили проектов

## Назначение

Профили расширяют универсальный шаблон правилами и документацией для конкретного типа проекта.

Общие правила хранятся в корневых документах и `.agents/`. Специфичные требования технологий размещаются в соответствующем профиле.

## Доступные профили

- `laravel/` — приложения на Laravel и PHP.
- `wordpress/` — темы, плагины и сайты на WordPress.
- `api/` — самостоятельные API и интеграционные сервисы.
- `frontend/` — frontend-приложения.

## Правила использования

1. При старте проекта координатор определяет его тип.
2. Выбирается один основной профиль. При необходимости подключаются дополнительные.
3. Координатор изучает инструкции выбранного профиля до составления технического плана.
4. Правила профиля дополняют общие правила, но не отменяют их.
5. Если правила противоречат друг другу, агент останавливается и запрашивает решение координатора.
6. Неиспользуемые профили не нужно подключать к проекту.

## Состав профиля

По мере необходимости профиль может содержать:

- `README.md` — назначение профиля и порядок применения.
- `TECH_STACK.md` — рекомендуемый стек технологий.
- `ARCHITECTURE.md` — архитектурные соглашения.
- `QUALITY_CHECKLIST.md` — специфические проверки качества.
- дополнительные инструкции и шаблоны.

Не создавай все файлы заранее без необходимости. Добавляй их по мере появления требований конкретного типа проекта.
