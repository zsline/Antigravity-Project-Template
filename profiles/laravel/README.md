# Профиль Laravel

## 1. Назначение

Профиль содержит дополнительные правила для проектов на Laravel и PHP. Он дополняет общие правила корневого `AGENTS.md`, но не заменяет их.

## 2. Обязательные документы проекта

Перед разработкой координатор должен определить необходимость следующих документов:

- `PROJECT.md` — описание продукта и границы MVP.
- `REQUIREMENTS.md` — функциональные и нефункциональные требования.
- `ARCHITECTURE.md` — архитектура приложения.
- `DATABASE.md` — модели данных и связи.
- `WORK_PLAN.md` — этапы разработки.
- `TASKS.md` — реестр задач.
- `QUALITY_CHECKLIST.md` — критерии качества.

## 3. Правила работы с Laravel

1. До написания кода изучить установленную версию Laravel и её официальную документацию.
2. Не переносить решения из старых версий Laravel без проверки совместимости.
3. Использовать стандартные механизмы Laravel там, где они подходят задаче.
4. Не помещать всю бизнес-логику в контроллеры.
5. Валидацию, авторизацию, обработку ошибок и транзакции проектировать явно.
6. Схему базы данных изменять через миграции.
7. Для моделей, связей и массового заполнения явно проверять корректность и безопасность.
8. Конфигурацию и секреты хранить вне исходного кода.
9. Не добавлять зависимости без обоснованной необходимости.

## 4. Основные зоны приложения

При проектировании определить ответственность следующих компонентов:

- Routes — маршрутизация.
- Controllers — обработка HTTP-запросов.
- Form Requests — валидация и, при необходимости, авторизация запросов.
- Models — работа с данными и отношениями.
- Services или Actions — бизнес-операции, когда их выделение оправдано.
- Policies и Gates — правила доступа.
- Jobs и Events — фоновые и событийные процессы, если они нужны.
- Resources — форматирование ответов API, если используется API.
- Tests — автоматизированные проверки.

Не создавай все компоненты автоматически. Используй только те, которые оправданы архитектурой проекта.

## 5. Работа с базой данных

- Изменения схемы выполняются миграциями.
- Внешние ключи и индексы добавляются по требованиям модели данных.
- Правила удаления связанных записей определяются явно.
- Для связанных операций проверяется необходимость транзакций.
- Избегай N+1 запросов и ненужных обращений к базе.
- Тесты не должны зависеть от случайного состояния локальной базы.

## 6. Безопасность

- Проверять авторизацию не только в интерфейсе, но и на сервере.
- Валидировать все недоверенные входные данные.
- Не раскрывать секреты и конфиденциальные данные в логах.
- Использовать CSRF-защиту для соответствующих веб-форм.
- Не обходить штатные механизмы аутентификации и авторизации без обоснования.
- Проверять права доступа к объектам, принадлежащим конкретным пользователям.

## 7. Проверки перед завершением задачи

В зависимости от проекта и окружения проверять:

- форматирование и стиль кода;
- корректность маршрутов;
- миграции;
- автоматические тесты;
- обработку ошибок;
- авторизацию;
- отсутствие регрессий.

Команды должны соответствовать фактическим зависимостям проекта. Не заявляй о прохождении проверок, которые не запускались.

## 8. Документация

При изменении маршрутов, моделей, API, бизнес-правил или конфигурации обновлять связанные документы.

При существенном изменении архитектуры сначала согласовать решение с координатором и зафиксировать его в журнале решений.

## 9. Официальные источники

- Документация Laravel: https://laravel.com/docs
- Документация PHP: https://www.php.net/docs.php

Версии документации выбираются по установленной версии Laravel и PHP.
